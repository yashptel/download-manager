# OpenDM for Windows

WinUI 3 (Windows App SDK 1.8), unpackaged, on the same Rust core as the
macOS app. The core is reached through C# bindings generated by
[uniffi-bindgen-cs](https://github.com/NordSecurity/uniffi-bindgen-cs).

> **Status:** written on macOS without a Windows toolchain. The Rust core and
> its integration test type-check for `x86_64-pc-windows-msvc`; the C# and
> XAML have never been compiled. Expect a round of compile fixes first.

## Prerequisites

- Windows 10 1809 or later (Windows 11 recommended)
- Visual Studio 2022 Build Tools with **Desktop development with C++** (MSVC
  and the Windows SDK, needed by Rust)
- [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0)
- [Rust](https://rustup.rs) with the MSVC toolchain
- Git and PowerShell

## Build

```powershell
scripts\build-windows.ps1              # x64 Release -> build\windows\OpenDM-x64\OpenDM.exe
scripts\build-windows.ps1 -Arch arm64
```

The script downloads the pinned aria2-next build and checks its SHA-256,
builds the Rust core (`opendm_core.dll`), installs the pinned C# bindings
generator into `build\tools` on first use, generates `OpenDM\Core\opendm_core.cs`,
copies the native files into `OpenDM\Native` and publishes the app. After one
run, `OpenDM\OpenDM.csproj` also opens and builds in Visual Studio.

Run against a scratch data folder during development:

```powershell
$env:OPENDM_DATA_DIR = "$env:TEMP\opendm-dev"
build\windows\OpenDM-x64\OpenDM.exe
```

## Test

```powershell
scripts\fetch-engine.ps1
cargo test -p opendm-core
```

The engine test kills aria2-next mid-download with `taskkill /F`, checks the
restart and the downloaded bytes, removal with file deletion, and history after
reopening. `python scripts\test-server.py` serves throttled files for trying
the app with many live downloads.

## Layout

| File | Role |
| --- | --- |
| `Program.cs` | Entry point; single instance through `AppInstance` |
| `App.xaml.cs` | Creates the core, window and tray icon; quits cleanly |
| `DownloadStore.cs` | Applies the core's changed rows on the UI thread |
| `DownloadItem.cs` | Row view model; raises a change per field |
| `DownloadList.cs` | The visible collection; small reorders become moves |
| `MainWindow.xaml(.cs)` | Title bar, sidebar, toolbar, list, dialogs, keys |
| `TrayIcon.cs` | Notification-area icon (H.NotifyIcon) |
| `Format.cs`, `Native.cs` | Formatting, links, Win32 helpers |

## List styles (to port from macOS)

The macOS app lets the user pick one of three list designs; the choice is
remembered and List is the default. The Windows app currently has only the
Columns table. Add the other two as alternative item templates on the same
virtualized list, switched by a three-way toggle in the toolbar and
Ctrl+1 / Ctrl+2 / Ctrl+3, saved in local settings:

| Style | Row height | Contents |
| --- | --- | --- |
| Cards | 104 | Card with a 10 px corner radius, inset 10 px from the sides and 4 px top and bottom, 1 px separator border. 36 px file icon; semibold name; status line in the status color with its symbol, plus speed and time left while downloading (failed rows show the error); full-width 5 px bar; "40% · 82 MB / 209 MB". A pill of Pause/Resume/Retry/Open, Show in folder, Copy address and Remove buttons at the top right. Selection is an accent outline. |
| List | 54 | 32 px icon; name; a 4 px bar only while unfinished; detail line such as "82 MB of 209.7 MB · 258 KB/s · 8 min left", in red with the error for failed rows. Two fixed button slots at the trailing edge: pause/resume/retry, and show in folder (finished rows, or on hover). |
| Columns | 26 | The existing table. Status shows a colored symbol and a short word ("Failed", with the error as a tooltip); progress, speed and time left only while they mean something. |

Status colors: downloading uses the accent color, paused orange, completed
green, failed red, queued a tertiary gray. The macOS sources are
`apple/Sources/OpenDM/RowCells.swift` (Cards and List) and `Cells.swift`
(Columns). Recheck the 5,000-row test in each style.

## Things to verify first

- **Compile errors** in XAML and C#, especially the generated bindings
  (`AllowUnsafeBlocks` is on) and the `TaskStatus` alias in `GlobalUsings.cs`.
- **Tray icon:** H.NotifyIcon 2.4.1 with Windows App SDK 1.8. Efficiency mode is
  disabled on purpose (`ForceCreate(false)`); it would throttle downloads.
- **Single instance:** a second launch must show the running window.
- **Close and exit:** closing hides the window; Exit in the tray menu stops
  the engine. Check that no `aria2-next.exe` remains.
- **Header alignment** with the list columns at 100% and 150% scaling.
- **Responsiveness** with 5,000 rows and 60 live downloads, compared with the
  macOS numbers in the root README.
